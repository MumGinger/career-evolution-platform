# Architecture Decision Records

ADRs record durable product and architecture decisions. Create or update an ADR when a decision changes a cross-capability boundary, domain meaning, data semantics, or a principle's application.

## Format

Each ADR contains: Title, Status, Context, Decision, Alternatives Considered, and Consequences. Do not rewrite history; supersede an accepted ADR with a new ADR when its decision changes.
